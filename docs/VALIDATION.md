# Проверка релиза 0.1

Дата: 2026-11-01. Среда: CachyOS, x86_64, systemd user session, Python 3.14.8. Проверка выполнялась на реальной машине, а не на подменённом Minecraft-процессе.

## Реальное развёртывание

- Mojang manifest вернул стабильный Minecraft 26.3, требуемая Java — 25.
- Paper API v3 вернул stable build 236; скачанный JAR проверен по SHA-256 источника.
- Eclipse Temurin JRE 25 установлен в пользовательский каталог, архив проверен по SHA-256 Adoptium.
- `uwucraft.service` проверен через `systemd-analyze --user verify`, включён, протестированы запуск, stop и повторный start. Linger включён; перезагрузка самой машины в этой проверке не выполнялась.
- Сервер вывел `Done (...)! For help, type "help"`; статус определяется по живому PID и времени его создания, а готовность — по выводу сервера.
- Minecraft SLP вернул `Paper 26.3`, protocol `777`, настоящие player counts.
- AuthMe 6.0.1 успешно enabled; ViaVersion/ViaBackwards 5.12.2 распознали сервер 26.3. Все три плагина получены из официальных релизов с SHA-256 GitHub.
- Случайный пароль администратора сохранён в приватном локальном файле. Пароли не включены в репозиторий или отчёт.

## Публичное подключение

Домашняя сеть оказалась за CGNAT. Сам по себе port forwarding не позволял принять вход через NAT провайдера. Для проверки был явно выбран account-free TCP relay bore.

1. Relay подключился и сообщил реально назначенный порт.
2. Прямой Minecraft SLP через публичный адрес вернул ожидаемую версию/MOTD сервера.
3. Независимая внешняя проверка mcsrvstat.us вернула `online=true`; первая проверка была без cache hit.
4. Headless клиент на `minecraft-protocol` 1.21.11 подключился через публичный relay. Через ViaBackwards прошёл login/configuration, получил play login packet и вошёл в мир сервера 26.3.
5. Клиент отправил `/register` для временного тестового аккаунта и получил подтверждение регистрации AuthMe.
6. В серверном логе подтверждён вход игрока (`joined the game`, `logged in with entity id`).
7. Временный игрок удалён из whitelist и базы AuthMe; удаление проверено по файлу whitelist и SQLite.

Это проверка реального сетевого клиента и регистрации. Это **не** тест Minecraft GUI, входа оплаченного Microsoft-аккаунта или многочасовой игры. Публичный адрес relay намеренно не закреплён в README: он зависит от конкретной установки и может меняться.

## Автоматические тесты

См. `tests/test_core.py` и GitHub Actions. Проверяются:

- валидность памяти, атомарная запись и права конфигурации, блокировка конкурирующих операций;
- отказ без EULA, сохранность повторного auto;
- подмена/исчезновение PID, запрет многострочной команды консоли;
- backup/restore, восстановление метаданных, retention при restore выбранной копии;
- ZIP path traversal и symlinks;
- запрет backup работающего сервера;
- отказ при hash mismatch с сохранением исходного файла;
- запрет HTTPS→HTTP redirect до запроса к HTTP-хосту;
- запрет передачи API key при redirect на другой host;
- проверка server-side Modrinth, реестр локального импорта, защита зависимого мода от удаления;
- отсутствие ложного подтверждения clipboard;
- positional whitelist CLI, проверка свойств и предупреждение offline-mode;
- страницы TUI, смена темы, сохранность предпочтения темы при NO_COLOR;
- внешняя проверка, возвращающая offline, не подменяется локальным listen.

Unit tests используют временные XDG-каталоги и mock API; они не доказывают работоспособность внешних сервисов. Воспроизводите live smoke test отдельно с принятой EULA. Зависимость minecraft-protocol используется только для проверки и не требуется самому uwucraft.

## Непроверенное / границы

- Полные live lifecycle Vanilla/Purpur/Fabric/Forge/NeoForge и реальный CurseForge API key не проверены.
- Перезагрузка ОС, длительная нагрузка, подключение большого числа игроков и восстановление после потери питания не проверены.
- Наличие `Restart=on-failure` и linger подтверждено конфигурацией, но не заменяет тест reboot/аварии.
- Бесплатный relay не даёт SLA, постоянного адреса и защиты от DDoS. Проверенное подключение не гарантирует будущую доступность.
- AuthMe сообщает о недоступной опциональной MaxMind GeoIP-базе без credentials; password registration/login от неё не зависит. Inventory protection требует отдельный PacketEvents; это ограничение не скрывается.
- Системная установка с отдельным service-user, встроенный sampler TPS/MSPT и профили нескольких серверов отсутствуют.
