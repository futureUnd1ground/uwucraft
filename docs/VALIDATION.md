# Проверки прямого создания сервера

Работа продолжена в существующем репозитории: lifecycle, установщики ядер, загрузки с хешами, резервные копии и контент сохранены. Новые CLI/TUI мастера вызывают общий `creation.create(CreateOptions, ...)`.

## Автоматические проверки

- EULA проверяется до установки зависимостей и любых изменений файлов.
- Существующие конфигурация и мир не перезаписываются.
- `--quick` не вызывает prompts; отрицательный сетевой результат даёт ненулевой exit code.
- Выбранные имя, версия, loader, режим аккаунтов, RAM, порт и max-players передаются общему backend.
- `server-ip=0.0.0.0`, port/max-players/mode и индивидуальный MOTD проверяются в установщике.
- Тест TUI нажимает настоящую кнопку, проверяет отказ без EULA, затем запуск backend в worker, результат и кнопку копирования.
- nftables: исключение в каждой IPv4 input base chain, сохранность чужих правил и policy, отсутствие дубликатов, явный отказ без root.
- Реальный `nft` выполняет JSON transaction в изолированном user/network namespace. Проверяются две действующие цепочки с drop policy, сохранность исходных SSH/counter правил и повторный вызов без изменений. Основной firewall машины не затрагивается.
- NAT-PMP: точные пакеты RFC 6886, TCP opcode, выбранные порты, lease и подключение сокета только к шлюзу.
- UPnP: SSDP discovery, control URL из XML описания, SOAP GetExternalIPAddress/GetSpecificPortMappingEntry/AddPortMapping; XML entities, внешние control URL и redirects отклоняются.
- Отказы UPnP переключают попытку на NAT-PMP, а не на иной способ доступа.
- При ошибке прав на ПК и CGNAT продолжается независимая внешняя проверка; ошибки сохраняются, доступность не объявляется подтверждённой.
- Частные, CGNAT, loopback, IPv6 и reserved IPv4 не показываются как публичные.
- `online=true` чужого Minecraft-сервера не доказывает идентичность новой установки: сверяется случайный идентификатор MOTD.
- Сохранены тесты CLI управления, backup/restore, ZIP, зависимостей контента, clipboard и тем.

Unit tests работают с временными XDG-каталогами и mock API. Native nft integration использует отдельный namespace; на CI без `unshare`/`nft` или разрешённых namespaces тест явно skipped. Положительный UPnP/NAT-PMP ответ от реального домашнего роутера в этой среде не получен — успешные сценарии проверены протокольными тестами, а не выданы за live-доказательство.

## Проверка на текущей машине

Управляемый сервер Paper уже существовал. Повторный `create` защищает его от перезаписи. Работающий Java PID и файл мира сохранены при миграции. Устаревший дополнительный сетевой unit отключён; новые команды его не используют.

`network configure` реально выполнил попытки настройки и внешний probe. Автоматическая настройка host nftables была отклонена, поскольку sudo требует авторизацию; приложение сообщило это и продолжило остальные шаги. Домашний роутер не предоставил UPnP/NAT-PMP, внешний Minecraft-порт не подтвердился. Код вернул ошибку, а не сообщение о публичной доступности.

HTTPS-сервис сообщил глобальный IPv4, но это не доказывает, что он принимает входящие соединения на этот ПК. Если роутер не сообщает WAN, приложение не может достоверно отличить CGNAT от других причин недоступности. Это ограничение явно описано в README.

Перезагрузка ОС, длительная игровая нагрузка, реальные оплаченные аккаунты и полные live lifecycle всех шести ядер в этой итерации не проверены. Положительная end-to-end проверка нового прямого публичного подключения невозможна без требуемых прав и подходящих условий у провайдера/маршрутизатора.


## Windows 0.3.0

Новый native workflow использует windows-latest с Python 3.11 и 3.14 и JDK 21. Проверки отделены от Linux-only nft/systemd тестов. Windows tests выполняют реальные PowerShell Get-NetRoute/Get-NetIPAddress, регистрацию/чтение/удаление per-user задачи, msvcrt locking, UTF-8 в кириллических путях, скачивание и запуск Temurin JRE ZIP. Реальный маленький Java JAR проверяет named-pipe console, принятие команды, падение с кодом 3, автоматический новый PID, штатный stop и повторный start. Этот fixture не выдаётся за Minecraft. Firewall-проверка только при явно включённом integration env и admin token; тест удаляет своё временное TCP-правило. Из Linux нельзя проверить интерактивное окно UAC, вход/выход/перезагрузку Windows и реального игрового клиента — эти проверки остаются ручными.


## Профили и Python bootstrap 0.4.0

Добавлены проверки изоляции файлов/консолей/units, глобального CLI --profile без утечки между вызовами, миграции старых units без рестарта, сохранности остальных профилей после backup/restore default, официального каталога и TUI выбора профиля/версии. Via plugins загружаются вместе до замены, ошибка загрузки оставляет прежние JAR. Windows native test запускает два реальных JVM fixture одновременно и останавливает один, проверяя работоспособность другого. Настоящий Paper также проверяется в именованном профиле: установка ViaVersion/ViaBackwards/ViaRewind, повторный запуск и строки Enabling для всех трёх плагинов.

Windows CI отдельно вызывает install.ps1 -BootstrapPython, даже когда системный Python присутствует: использует вложенный pinned официальный installer (отдельно проверен и путь скачивания при отсутствии payload), проверяет SHA-256 и Authenticode PSF и устанавливает отдельный Python без winget. Release packaging вкладывает те же байты в vendor/python-installer.exe внутри Windows ZIP; бинарник не хранится в Git и не попадает в wheel. Проверка всех игровых клиентов, всех исторических модовых ядер и всех версий Via не подменяется fixture или списком опубликованных API версий.
